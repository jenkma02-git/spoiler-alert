# Spoiler Alert

An AI evaluation project that asks: do LLM-generated answers about reality TV respect a viewer's spoiler boundary?

Example: a viewer has watched episodes 1–4 of a show and asks, "Are Maya and Theo going to make it?" A good answer helps without revealing anything from episodes 5 onward. A spoiler can be obvious ("she says no at the altar") or subtle ("don't get too attached").

## Why this project exists

I spent eight years as a QA automation engineer, working in Selenium and then Cypress. This project is how I'm learning to apply the same habits to AI systems, where the output changes from run to run and "correct" is often a judgment call. Some of those habits are known expected results, being suspicious of the tests themselves, and covering both missed bugs and false alarms.

It's also a Promptfoo learning exercise alongside the Engenious AI testing course. My notes on what I learn are in [LEARNINGS.md](LEARNINGS.md).

## Evaluation approach

**Golden dataset.** A small set of responses where I decided the expected result (PASS = no spoiler, FAIL = spoiler) before running anything. These labels are the answer key.

**LLM-as-a-judge with `llm-rubric`.** Promptfoo's `llm-rubric` assertion sends a response to a second model (the judge) along with written grading instructions (the rubric). The judge returns PASS or FAIL and a reason.

**Testing the judge first.** An LLM judge can be wrong, so the current milestone tests the judge itself: does it agree with my labels? The responses are fixed text, not generated by a bot. That way any disagreement comes from the judge or the rubric, not from a bot behaving differently between runs.

**Deterministic assertions** (exact text checks like `not-icontains`) are planned but not implemented yet. See [Current status](#current-status).

## How it's built

| Part | What it is | Where |
|---|---|---|
| System under test | The judge: model + rubric | Model: `promptfooconfig.yaml` (`defaultTest`). Rubric: `rubrics/spoiler-free.txt` |
| Test inputs | 8 fixed responses to one fictional scenario, each with a human label | `tests/judge-calibration.yaml` |
| "Bot" | Promptfoo's `echo` provider, which returns each fixed response unchanged so it can be graded | `promptfooconfig.yaml` (`providers`) |

- **Scenario:** a made-up show, *Engaged Sight Unseen*. Because it's fictional, there's no real-world episode data to verify, and the judge can't rely on knowing the plot. The rubric lists what the viewer has and hasn't watched.
- **Judge:** `groq:openai/gpt-oss-120b`, temperature 0, on Groq's free tier. It started as `qwen/qwen3.8-27b` and was switched because of rate limits. See LEARNINGS.md.

## Getting started

You need Node.js (tested with 24.21; current Promptfoo requires 22.22 or later) and a free [Groq API key](https://console.groq.com/keys).

```bash
cp .env.example .env        # then paste your GROQ_API_KEY into .env
npx promptfoo@latest eval -c promptfooconfig.yaml --no-cache
npx promptfoo@latest view   # opens the results in a browser
```

Run from the repo root so Promptfoo finds `.env`. Use `--no-cache` when checking consistency. Without it, Promptfoo replays earlier judge answers instead of asking again.

**Reading the results:** PASS/FAIL in the report is the judge's verdict (PASS = spoiler-free, FAIL = spoiler), not a measure of whether things went well. The judge agrees with me when its verdict matches the `[human: ...]` label in the case name.
